# ch03 错题 — 控制流：条件与循环

## [ch03] 练习 5 — 循环体内过早 return,第一次不匹配就放弃

- **状态**：✅ 已改正（2026-09-01 代码审读确认：`return None` 已移到循环外、与 for 对齐）
- **题目**：找出 n 的最小因子,是质数则返回 None

### 错误代码

```python
def find_first_divisor(n):
    for m in range(2, n):
        if n % m == 0:
            return m
        else:
            return None     # ← 问题在这
```

### 错误表现

`find_first_divisor(15)` 返回 `None`,正确答案是 `3`。
m=2 时 `15 % 2 == 1`(不整除)→ 走 else → `return None` → 函数立刻结束,
m=3 根本没被检查到。

### 错因分析

两个概念混在一起：

1. **某一次不匹配 ≠ 整体没找到**。循环的意义就是多次尝试,"没找到"的结论
   只有循环**完整跑完**后才成立。
2. **return 会立刻终止整个函数**,不只是跳出这次 if/else。它在循环体内,
   等于第一次判断就宣判了整个循环的死刑。

### 正确写法

```python
def find_first_divisor(n):
    for m in range(2, n):
        if n % m == 0:
            return m
    return None              # ← 缩进和 for 对齐:循环全部结束后才执行
```

进阶写法(循环的 else,3.4 节):

```python
for m in range(2, n):
    if n % m == 0:
        return m
else:
    return None              # 没被 break/return 打断时执行
```

### 一句话教训

> **"没找到"只能在循环全部跑完之后下结论**——结论性 return 要和 for 对齐,不能缩进在循环里。

## [ch03] 练习 6 — range() 传入列表崩溃 + 下标与值混淆

- **状态**：⬜ 待改正（第二轮：旧代码已删除,但函数体现在是空的 `while True:`,
  属于语法错误,会导致整个模块无法导入、8 个测试全部报错,必须先补全）
- **题目**：返回 target 在 guesses 中第几次被猜中(从 1 开始数)

### 错误代码(第一版)

```python
def guess_game(target, guesses):
    count = 0
    while True:
        for i in range(guesses):     # ① 崩溃点
            if target == i:          # ② 比错了对象
                return count         # ③ 少 +1
            else:
                count += 1
```

### 错误表现

```
TypeError: 'list' object cannot be interpreted as an integer
```

### 错因分析

三处问题：

1. **`range(guesses)`**:range() 只接受整数,传入列表直接 TypeError。
   想遍历列表可以直接 `for x in guesses`,不需要 range。
2. **`target == i`**:`i` 是**下标**(0,1,2…),`guesses[i]` 才是那个位置上的**值**。
3. **返回值差 1**：题目要"第几次"(从 1 数)，下标从 0 数，返回时要 +1。

### 正确写法

```python
def guess_game(target, guesses):
    i = 0
    while True:
        if guesses[i] == target:
            return i + 1     # 下标 + 1 = 次数,不需要单独的 count 变量
        i += 1
```

### 一句话教训

> **`i` 是位置,`guesses[i]` 是位置上的东西**；下标从 0 数、次数从 1 数，差 1。

## [ch03] 附加 — 编辑器自动补全混入无关 import

- **状态**：⬜ 待改正（第二轮检查仍在第 9 行,删除即可）

### 错误代码

```python
from sqlite3.dbapi2 import SQLITE_DBCONFIG_RESET_DATABASE
```

### 错因分析

编辑器自动补全弹窗时误按回车，把一个跟题目毫无关系的模块导入项插进了文件。
这类"幽灵 import"不报错，但会让代码依赖不明不白的东西。

### 预防方法

- 每次按补全回车前瞄一眼插入的是什么
- 提交前扫一遍 import 区，只保留自己真的用到的
- Pylance 会把未使用的 import 标灰，看到灰色的就删掉

### 一句话教训

> **import 区只留自己写的**——补全弹窗的回车要过脑。
