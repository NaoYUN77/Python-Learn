# ch07 错题 — 错误与异常

## [ch07] 练习 3 — 型号接错：FileExistsError ≠ FileNotFoundError

- **状态**：✅ 已改正（2026-09-02 测试 8/8 通过确认）
- **题目**：load_json(path)：文件不存在 → None；坏 json → None

### 错误代码

```python
except (FileExistsError, json.JSONDecodeError):
    return None
```

### 错误表现

文件不存在时 `FileNotFoundError` 接不住，直接穿墙炸穿测试——
正好是"except 声明的型号不是下层真正抛的型号"的现场教学。

### 错因分析

一字之差，意思完全相反：FileNot**Found** = 文件**不存在**（要接的）；
File**Exists** = 文件**已存在**（`open(..., "x")` 拒绝覆盖时抛）。
自动补全输入 `File` 后弹窗两项相邻，误选。

### 正确写法

```python
except (FileNotFoundError, json.JSONDecodeError):
    return None
```

### 一句话教训

> **except 型号必须和下层信号对上，接不住就是裸奔**——型号名逐字符读，
> NotFound 和 Exists 是反义词。

## [ch07] 练习 4 — 边界写错：`== 100` 应为 `> 100`

- **状态**：✅ 已改正（2026-09-02 测试 8/8 通过确认）
- **题目**：set_score(score)：0~100 返回 score；负数或**超过** 100 抛 ValueError

### 错误代码

```python
if score < 0 or score == 100 :
    raise ValueError(f"分数必须在 0~100: {score}")
```

### 错误表现

`set_score(100)` 会把满分炸成 ValueError——测试第二条 assert 直接失败。

### 错因分析

题目说"超过 100 抛"，`> 100` 才是越界；`== 100` 把合法边界值误判成非法。
写条件时把"100 这个点"想成了"越界的开始"。

### 正确写法

```python
if score < 0 or score > 100:
    raise ValueError(f"分数必须在 0~100: {score}")
```

### 一句话教训

> **边界值要单独过一遍脑子**——"0~100 含两端"意味着 0 和 100 都合法，
> 写完条件把 0、100、-1、101 四个值代进去验一遍。

## [ch07] 练习 6 — 裸 except（本章铁律一号，练习说明写了扣分）

- **状态**：✅ 已改正（2026-09-02 测试 8/8 通过确认）
- **题目**：describe_error(func)：三个具体型号各返回一词，其他异常原样转发

### 错误代码

```python
    except KeyError:
        return "key"
    except:
        raise
```

### 错因分析

意图对（"其他异常转发"），但转发根本不需要写——没被认领的异常
本来就不进任何 except，自动穿过整个结构向上飞（异常电梯）。
`except:` 裸写还会吞 `KeyboardInterrupt`（Ctrl+C）和 `SystemExit`。
想转发的冲动 = Go 里每层 `return err` 的肌肉记忆，但 Python 的
自动上传让这个"搬运"动作多余。

### 正确写法

```python
    except KeyError:
        return "key"
    # 没接住的自动上传,什么都不用写
```

### 一句话教训

> **不接也是一种正确处理**——except 永远写具体型号；转发不用代码，
> 异常自己会飞。

## [ch07] 附加 — 幽灵 import 第五次（双幽灵·套娃款）

- **状态**：✅ 已改正（2026-09-02 测试通过确认，import 区已清）
- **前科**：ch03 sqlite3 → ch04 winreg → quiz calendar（半截）→ ch06 asyncio → 本次

### 错误代码

```python
import json
from json.decoder import JSONDecodeError
from shutil import RegistryError
```

### 错因分析

双幽灵：第一行全代码用的是 `json.JSONDecodeError`（前缀写法），顶部的
`from json.decoder import ...` 完全多余；第二行 `RegistryError` 是 Windows
注册表的异常，与本章毫无关系，且 shutil 本身都没 import——补全嵌套误选
（打了关键字、弹窗选了里层符号，外层包也一起被塞了进来）。
本次 exercises 顶部没写 import json、要求学员自己加——加了，但也多带了两行。

### 一句话教训

> **交卷前扫 import 区是固定动作**——没用到的整行删，"整行删"三字
> 第五次应验；补全弹窗里出现了上下文无关的词（注册表？）直接警觉。

## [ch07] 风格 — 冒号前空格第四章连犯 + 逗号方向反

- **状态**：✅ 已改正（2026-09-02 测试通过确认）
- **前科**：ch03（`if x :`）→ ch04（`def inner() :`）→ ch06（`f :`）→ 本次

### 错误代码

```python
try :
    ...
f = open(path ,"w" , encoding='utf-8')
```

### 规范写法（PEP 8）

```python
try:
    ...
f = open(path, "w", encoding="utf-8")
```

### 一句话教训

> **冒号紧贴、逗号贴前空后**——连续四章了；交卷前全文搜 ` :` 和 ` ,`
> 两个模式，5 秒钟扫完全文。
