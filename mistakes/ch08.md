## [ch08] 练习 3 — 守门 raise 写了，正事没干

- **状态**：✅ 已改正（2026-09-03 盘面核验：`self.balance += amount` 已在）
- **题目**：BankAccount.deposit(amount)：amount <= 0 时 raise ValueError，否则余额加 amount

### 错误代码（当时的盘面）

```python
def deposit(self, amount):
    if amount <= 0:
        raise ValueError(f"存款必须为正数: {amount}")
    # ← 守门写了,门后面的正事忘了干
```

### 错误表现

deposit(50) 不报错也不加钱——余额纹丝不动，测试 `balance == 150` 失败。

### 错因分析

注意力全花在"把 ch07 的 raise 写对"上，写完守门 if 就以为方法完成了。
**守门只是检查，检查完还得干活**——if/raise 之后的代码才是方法的主业。

### 正确写法

```python
def deposit(self, amount):
    if amount <= 0:
        raise ValueError(f"存款必须为正数: {amount}")
    self.balance += amount
```

### 一句话教训

> **守门 ≠ 干活**——raise 拦住的是坏人，门里还等着你办正事。

## [ch08] 练习 8 — 累加器缩进在循环内（每轮清零）

- **状态**：✅ 已改正（2026-09-03 盘面核验：`best = ""` 已移出循环）
- **题目**：loudest(items)：返回 speak() 结果最长者

### 错误代码（当时的盘面）

```python
for i in items:
    best  = ""          # ← 缩进在 for 里面
    result = i.speak()
    if len(result) > len(best):
        best = result
return best
```

### 错误表现

每次循环 best 都被清成 ""——"谁最后一轮谁赢"，前面全白比。

### 错因分析

累加器（这里是"最长者"）必须在**循环外**初始化一次；
放循环内 = 每轮重新开始，比较对象永远是空串。
和 ch03"循环内过早 return"是同族病：**缩进决定"每轮重来"还是"全程累计"**。

### 正确写法

```python
best = ""
for i in items:
    result = i.speak()
    if len(result) > len(best):
        best = result
return best
```

### 一句话教训

> **累加器/比较器放循环外**——缩进一格之差，"累计"变"每轮清零"。

## [ch08] 练习 9 — 手滑三连（拼写 + 幽灵属性/方向反 + 漏一行）

- **状态**：✅ 已改正（2026-09-03 盘面核验：三处均已改对）
- **题目**：SafeAccount：_balance 受保护 + balance() 只读窗口 + 守门 deposit/withdraw

### 错误代码（当时的盘面）

```python
def disposit(self, amount):              # ① 拼写:deposit 写错
    if amount <= 0:
        raise ValueError(f"存款必须为正数: {amount}")
    self.amount += self._balance         # ② amount 不是属性;方向也反了
def withdraw(self, amount):
    if amount > self._balance:
        raise ValueError(f"余额不足: {self._balance} < {amount}")
                                         # ③ 扣款的正事没干(练习 3 同款)
```

### 错因分析

① **disposit**：手滑拼写，笔误史 +1（fist/itme/test/_name_/disposit）——
拼错的方法名测试直接 AttributeError，反而最容易发现。
② **self.amount += self._balance**：双重错——`amount` 是参数不是属性
（幽灵属性）；且 `+=` 的左边是被加的对象，把余额加进 amount 正好写反，
正确方向是**余额 += 存款额**。
③ 漏扣款行：练习 3"守门后忘正事"同章复发（withdraw 那次先漏了）。

### 正确写法

```python
def deposit(self, amount):
    if amount <= 0:
        raise ValueError(f"存款必须为正数: {amount}")
    self._balance += amount

def withdraw(self, amount):
    if amount > self._balance:
        raise ValueError(f"余额不足: {self._balance} < {amount}")
    self._balance -= amount
```

### 一句话教训

> **`+=` 读作"左边 = 左边 + 右边"**——落笔前把左边念一遍；
> 方法名拼错会立刻报 AttributeError，照着报错改就行，别慌。

## [ch08] 附加 — 幽灵 import 第六次（首次带副作用）

- **状态**：⬜ 待改正（2026-09-03 复查：L17 仍在）
- **前科**：ch03 sqlite3 → ch04 winreg → quiz calendar（半截）→ ch06 asyncio → ch07 双幽灵 → 本次

### 错误代码

```python
from boost.ch05_tuples import result
```

### 错因分析

本次是**六连里最重的一次**：① `result` 全程未用——幽灵；
② import 有副作用——import 会执行 boost/ch05_tuples.py 的**顶层代码**，
它的演示没加 `__name__` 守卫，于是每次跑 ch08 测试都先刷一屏 boost 的演示输出。
（ch09 正面讲：import = 找到 → 执行顶层 → sys.modules 记账。）

### 一句话教训

> **import 不是免费的**——它会把那个文件从头到尾跑一遍；
> 没用的整行删，自己的演示一定加 `if __name__ == "__main__":` 守卫。
