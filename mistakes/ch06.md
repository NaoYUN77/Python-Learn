# ch06 错题 — 输入输出与文件

## [ch06] 练习 1 — 年份补零位数：:02d 应为 :04d

- **状态**：✅ 已改正（2026-09-02 测试 8/8 通过确认）
- **题目**：format_date(2026, 9, 1) → "2026-09-01"，且 format_date(1, 1, 1) → "0001-01-01"

### 错误代码

```python
return f"{y:02d}-{m:02d}-{d:02d}"
```

### 错误表现

`format_date(1, 1, 1)` 返回 `"01-01-01"`，测试期望 `"0001-01-01"`，第三条 assert 失败。

### 错因分析

`:02d` 的 2 是"**至少**几位，不足补零"——是下限不是定长。月/日两位够用，
年份是四位数，下限必须是 4。

### 正确写法

```python
return f"{y:04d}-{m:02d}-{d:02d}"
```

### 一句话教训

> **格式说明符的位数 = 补零下限**——按字段实际位数定：年 4、月/日 2。

## [ch06] 练习 7 — dump 漏了 ensure_ascii=False（本章划的重点）

- **状态**：✅ 已改正（2026-09-02 测试 8/8 通过确认；中途曾把参数误挂到 open 上，
  经 basedpyright 报错解读后改正——"参数属于哪个函数"已单独讲过）
- **题目**：save_data 把 dict/list 存成 json 文件

### 错误代码

```python
json.dump(data, f)
```

### 错误表现

测试**能过**（\u 转义读回来可还原，往返相等），但文件里中文全是
`"\u5c0f\u660e"` 天书，不可读。

### 错因分析

默认 `ensure_ascii=True` 会把非 ASCII 字符转义。README 6.5 明确强调过
Windows/中文场景要显式传 `ensure_ascii=False`。测试没卡它是因为转义可逆——
"测试通过"不等于"符合要求"的典型例子。

### 正确写法

```python
json.dump(data, f, ensure_ascii=False, indent=2)
```

### 一句话教训

> **存中文必带 ensure_ascii=False**——json 文件是给人看的，不是给 \u 看的。

## [ch06] 练习 6 — 恒真的哑门卫 `if line:`（这次运气好）

- **状态**：⬜ 待改正（2026-09-02 测试 8/8 通过，但**该代码未改**——
  恒真门卫仍在，语义恰好等价纯属运气；改后需再确认）

### 错误代码

```python
for line in f :
    if line:
        line_count += 1
        word += len(line.split())
```

### 错因分析

门卫模式是从练习 5 抄的，但练习 5 的 `if stripped:` 是 **strip() 之后**判空；
这里没 strip，文件遍历产出的每行至少含 `\n`，永远非空，`if line` 恒为真，
等于没写。本次语义恰好等价（行数本该全数），纯属运气；换场景就是 bug。
模式迁移时要连同**前提条件**一起迁。配套概念已讲透：strip 前后真假值
（`"\n"` 非空为真 / `""` 为假）。

### 正确写法

```python
for line in f:
    line_count += 1
    word_count += len(line.split())
```

### 一句话教训

> **抄模式先问前提**——判空门卫只在 strip 之后才有意义，文件行永远非空。
