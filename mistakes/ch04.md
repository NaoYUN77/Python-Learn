## [ch04] 练习 5 — join 分隔符少了空格

- **状态**：✅ 已改正（2026-09-01 测试 9/9 通过确认）
- **题目**：用 **kwargs 生成 "name: 小明, age: 18" 格式的个人简介

### 错误代码

```python
def profile(**kwargs):
    return ",".join(f"{k}: {v}" for k, v in kwargs.items())
```

### 错误表现

`profile(name="小明", age=18)` 返回 `"name: 小明,age: 18"`，
测试期望 `"name: 小明, age: 18"` —— 逗号后少一个空格。

### 错因分析

join 的分隔符是**逐字使用**的：`","` 就只有逗号，不会自动补空格。
题目注释里给的提示 `", ".join(...)` 是逗号+空格两个字符。

### 正确写法

```python
return ", ".join(f"{k}: {v}" for k, v in kwargs.items())
```

### 一句话教训

> **join 的分隔符要照着目标输出逐字符写**——想要 ", " 就得写 `", "`。

## [ch04] 附加 — 演示代码误追加到 exercises.py 末尾

- **状态**：⬜ 待改正（2026-09-01 审读发现）
- **题目**：无关问题：文件末尾多出演示代码

### 错误代码

```python
def area(width, height):
    return width * height


print(wrap_call(area, 3, height=5))
```

### 错误表现

每次运行 `python -m ch04.test_exercises` 都会先打印：
```
call area
15
```
测试虽然 9/9 通过，但这几行输出不属于测试结果。

### 错因分析

学员在向 Agent 提问时（讨论 wrap_call 的执行流程）把验证代码直接写进了练习文件。
**exercises.py 是"作业本"，顶层代码会在每次导入时执行**（test_exercises import 它，
所以每轮测试都先跑这段）。验证想法应该用：临时文件、REPL、或对照 answers.py 的
`if __name__ == "__main__"` 演示块写法（它只在直接运行时执行，被导入时不执行——
这正是 `__name__ == "__main__"` 存在的意义）。

### 正确写法

删掉这 5 行；或如果确实想保留演示，移入 `if __name__ == "__main__":` 块内。

### 一句话教训

> **练习文件只放练习**——想试验代码用临时文件或 REPL，想保留演示就套
> `if __name__ == "__main__":`（学到的 __name__ 知识正好用上）。
